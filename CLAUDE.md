# Office Game (Alfa-Bank concept)

Студенческий проект. Браузерная 2D-игра для телефона, мотивирующая сотрудников приходить в офис: задания выполняются физически в офисе, за них начисляется внутриигровая валюта, которую можно обменять на награды (в том числе «реальные» из каталога). Игра нигде не публикуется.

Визуальный стиль вдохновлён Hotline Miami 2: Wrong Number: детализированный пиксель-арт, неон, резкий контраст, CRT/VHS-эффекты, тряска камеры. Игра вертикальная (портретная ориентация телефона). Квартира игрока и офис показаны в виде 3/4 сверху (стены и мебель спереди, видны лица и одежда персонажей), катсцены интро — вид сбоку в комикс-панелях. Пропорции персонажей и предметов реалистичные. Все ассеты (спрайты, музыка, шрифты, персонажи) — собственные или под свободной лицензией; ассеты оригинальной игры не используются.

## Версия

Только **веб**: Web-экспорт Godot, игра открывается в браузере телефона (Android и iPhone) и работает только в Wi-Fi офиса. Нативные приложения для Android и iOS отложены, их код лежит в ветке `iOS-and-Android-application`; в `main` их не возвращать без решения владельца проекта.

## Стек

### Клиент

| Область | Выбор |
|---|---|
| Движок | Godot 4.x (последний stable) |
| Язык | GDScript со строгой статической типизацией (не C#: C# не экспортируется в Web) |
| Рендерер | Compatibility (WebGL 2) — максимальный охват браузеров телефонов |
| Разрешение | Базовое 360×640 (портрет), stretch mode `viewport`, aspect `expand`, целочисленное масштабирование, фильтр текстур `Nearest`, snap 2D-трансформаций к пикселям |

| UI | Godot Control-ноды, пиксельный шрифт, темы `.tres` |
| Аудио | Audio buses Godot (музыка, SFX, UI) |
| Локализация | Встроенная (`tr()`, CSV/PO), основной язык — русский |
| Сеть | Официальный клиент `nakama-godot` (HTTP + WebSocket) |
| Тесты | GdUnit4 |
| Линт/формат | gdtoolkit (`gdlint`, `gdformat`) |

### Платформенный слой

Функции, которых нет в ядре Godot, закрыты интерфейсом `PlatformServices` (автозагрузка) с двумя реализациями: веб (`client/platform/web`, браузер телефона) и эмулятор датчиков на ПК для отладки (`client/platform/desktop`).

| Функция | Веб |
|---|---|
| Сканирование QR | `JavaScriptBridge` + `getUserMedia` + jsQR |
| Лица и улыбки | MediaPipe Face Landmarker |
| Шаги, наклон | DeviceMotion |
| Уведомления | Notification API (пока открыта вкладка), Web Push от сервера — позже |
| Выбор фото из галереи | `JavaScriptBridge` + `<input type="file">` |
| Предметы, поза, метки, речь | пока нет: задания идут в упрощённой экранной версии |

Игровой код обращается только к `PlatformServices`, никогда напрямую к `JavaScriptBridge`.

### Сервер

| Область | Выбор |
|---|---|
| Игровой сервер | Nakama (open-source, Apache 2.0): аутентификация, аккаунты, кошелёк с леджером, хранилище, лидерборды, RPC |
| Серверная логика | Go runtime-модуль Nakama (плагин, собирается образом `heroiclabs/nakama-pluginbuilder` той же версии, что и сервер) |
| БД | PostgreSQL |
| Аутентификация | Логин + пароль, аккаунты создаёт только администратор (самостоятельной регистрации нет). Под капотом email-аутентификация Nakama: хук `BeforeAuthenticateEmail` превращает запрос во вход по username без создания аккаунта, остальные способы входа отключены. Сессия 7 дней без продления |
| Роли и департаменты | Роль (`admin`/`player`) и департамент — в metadata аккаунта (пишет только сервер). Департаменты — системные объекты storage `departments`, админ создаёт новые |
| Админка | React + TypeScript + Vite, клиент `nakama-js`; вызывает админские RPC (доступы и департаменты, статистика и аудит активности игроков, ограничения рабочего времени; далее каталог наград, задания, модерация обменов) |
| Локальный запуск | Docker Compose (Nakama + PostgreSQL) |
| Тесты | `go test` |
| Линт | `golangci-lint` |

```
[Godot-клиент: Web, браузер телефона]
        │  HTTPS / WebSocket (nakama-godot)
        ▼
[Nakama + Go-модуль] ── PostgreSQL
        ▲
        │  HTTPS (nakama-js)
[Админка React]
```

## Обязательные правила

1. **Сервер — единственный источник истины.** Клиент никогда не начисляет валюту, не засчитывает задания и не выдаёт награды. Клиент отправляет действие через RPC, сервер проверяет и меняет состояние. Офлайн-режима и локальной заглушки сервера нет: игра всегда работает через сеть.
2. **Экономика только через кошелёк Nakama** (`WalletUpdate` с метаданными операции). Каждое начисление и списание пишется в леджер. Все RPC, меняющие баланс, идемпотентны (ключ операции от клиента, проверка на сервере).
3. **Проверка присутствия в офисе — минимум два фактора, проверяются на сервере:**
   - ротируемые QR-коды входа и выхода на экране в офисе (TOTP-подобный токен, срок жизни 30–60 с, секрет только на сервере, экран получает коды по HTTP-ключу). Между входом и выходом игрок «в офисе»: только тогда засчитываются задания, статичные коды комнат и встречи с коллегами;
   - внешний IP сети офиса (`OFFICE_NETWORKS`): вне сети офиса сервер отклоняет любой игровой RPC, игра доступна только в корпоративном Wi-Fi.
4. **Антифрод на сервере:** лимиты начислений в день, запрет повторного использования QR-токена, журнал подозрительных действий, ручное подтверждение обмена на дорогие награды.
5. **Доступ выдаёт администратор.** Игрок не может создать аккаунт сам; у каждого игрока обязателен департамент из списка.
6. **Секреты** (ключи Nakama, TOTP-секреты, пароли БД) не коммитятся. Только через переменные окружения и `.env` в `.gitignore`.
7. **Платформенные API** — только через `PlatformServices` (см. выше).
8. **Работа важнее игры.** Сервер ограничивает игру: личный набор заданий на рабочий день, пауза между заданиями, часы заданий и лимит непрерывной игры с отдыхом (`limits.go`, `play.go`). Значения меняет админ. Мини-игру лимит не прерывает: отдых начинается после неё. Развлекательные уведомления — только вне рабочего времени.


## Соглашения

- GDScript: статические типы везде, `snake_case` для функций и переменных, `PascalCase` для классов и нод, один скрипт — одна ответственность, сигналы вместо прямых ссылок между несвязанными сценами.
- Go: стандартный `gofmt`, ошибки не игнорируются, каждое RPC валидирует входные данные.
- Коммиты: Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`).
- Основная ветка: `main`.
