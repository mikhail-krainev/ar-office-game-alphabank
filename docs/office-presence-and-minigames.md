# Присутствие в офисе, перемещение по комнатам и мини-игры

Заметки по итогам обсуждения (2026-09-16).

**Статус на 2026-09-17.** Реализовано в клиенте: мини-игры на камере, микрофоне, акселерометре и шагомере,
переход по комнатам через статичные QR, ротируемый QR-код присутствия (экран у ресепшна плюс проверка в
заглушке сервера), нативный Android-плагин и эмуляция датчиков на ПК. Подробности — в README.
Игра «Найди красное» заменена на «Найди предмет»: распознавание обычных офисных вещей через ML Kit
image labeling, однообразного поиска одного цвета больше нет.
Отложено: BLE-маяки, проверка внешнего IP офиса (нужен настоящий сервер), плагин для iOS, датчики в Web,
офлайн-распознавание речи через Vosk.

**Статус на 2026-09-23.** Правила перенесены в Go-модуль Nakama, заглушки больше нет. Экран у ресепшна
показывает два кода: вход и выход. Между ними игрок «в офисе»: только тогда засчитываются задания,
статичные коды комнат и встречи с коллегами; незакрытый интервал заканчивается с днём. Дыра «отсканировал
вход, ушёл домой и сканирует фото кодов комнат» остаётся до второго фактора (геозона или IP офиса).

**Статус на 2026-09-25.** Второй фактор сделан: внешний IP офиса (`OFFICE_NETWORKS`, `server/modules/network.go`).
Он проверяется на входе по коду и на каждом RPC, который засчитывает присутствие: задания, коды комнат,
выбор коллеги. Настройка — в `docs/web-testing-on-iphone.md`.

## 1. Проверка «игрок в офисе»

### Решение: внешний IP офиса

Телефон подключён к Wi-Fi офиса → запросы к Nakama приходят с внешнего (NAT) IP офиса → сервер сверяет IP с белым списком.

Почему так:

- работает на всех платформах, включая Web (v2);
- не нужны разрешения на устройстве;
- клиент не может подделать IP: проверка полностью на сервере (правило 1 из CLAUDE.md).

Отклонённые варианты:

- **Проверка SSID Wi-Fi** — SSID легко подделать своей точкой доступа. На iOS нужен entitlement «Access WiFi Information» и разрешение на геолокацию, на Android 10+ — разрешение на геолокацию, в Web SSID недоступен.
- **Геолокация как основной фактор** — в помещении погрешность GPS 10–50 м, координаты легко подменить (mock location). Остаётся только как слабый запасной фактор (детект подмены: Android `Location.isMock()`, iOS 15+ `sourceInformation.isSimulatedBySoftware`).

### Детали реализации

- IP клиента в Go-модуле: `ctx.Value(runtime.RUNTIME_CTX_CLIENT_IP)`.
- Если перед Nakama стоит reverse proxy — настроить доверие к `X-Forwarded-For`, иначе сервер видит IP прокси.
- Белый список — набор диапазонов CIDR в конфиге сервера (через env, не в репозитории). У офиса может быть несколько адресов.
- Добавить IPv6-префикс офиса: телефон может ходить через IPv6.
- Исключить IP VPN-шлюза: иначе корпоративный VPN из дома выглядит как офис.
- Проверять на **каждом** RPC задания, а не один раз при входе: игрок мог уйти с открытой игрой.
- Игрок на мобильном интернете → задание недоступно, подсказка «подключись к Wi-Fi офиса».
- Демо / студенческий стенд: «офис» = внешний IP сети университета или общежития. Локально в Docker сервер видит IP bridge-сети → отдельный dev-список через env.

## 2. Перемещение по комнатам офиса

### Модель: зоны, а не координаты

Комната реального офиса = комната в игре. Позиция игрока хранится как **зона**. При смене зоны персонаж сам идёт в нужную комнату по пути (`AStarGrid2D` / `NavigationAgent2D`). Внутри комнаты персонаж двигается тапами.

### Основной способ: BLE-маяки

Сканировать QR при каждом переходе между комнатами быстро надоест, поэтому зона определяется автоматически по BLE.

- **Железо:** рассчитываем на маяки, которые уже есть в офисе. Многие корпоративные точки доступа Wi-Fi (Cisco, Aruba, Juniper Mist) имеют встроенный BLE. Нужно подтвердить у IT (см. «Вопросы»). Если маяков нет — вернуться к вопросу (запасные варианты: ESP32 со своей прошивкой ~300–500 ₽ за шт, старые Android-телефоны как маяки).
- **Софт — только бесплатный:**
  - Android — AltBeacon Android Beacon Library (Apache 2.0);
  - iOS — CoreLocation (iBeacon), встроен в систему;
  - Web — BLE не поддерживается, только QR.
- **Формат:** iBeacon — читается и на Android, и на iOS.
- **Точность:** реально — уровень комнаты (помогают стены), а не метры. RSSI шумит, поэтому нужны:
  - сглаживание (скользящее среднее или фильтр Калмана);
  - гистерезис: зона меняется, только если другой маяк сильнее на X dBm дольше N секунд, иначе персонаж дёргается на границе комнат.
- **Ограничения платформ:**
  - iOS: iBeacon виден только через CoreLocation и только для заранее известных UUID, нужно разрешение на геолокацию, фоновое сканирование ограничено → трекаем, пока игра открыта;
  - Android 12+: разрешение `BLUETOOTH_SCAN` (с флагом `neverForLocation` можно без геолокации).
- **Интеграция:** через `PlatformServices` (например, сигнал `zone_changed`), игровой код с BLE напрямую не работает.
- **Безопасность:** UUID статичного маяка легко клонировать → зона по BLE годится для навигации, но не является доказательством присутствия для наград.

### QR-коды: три разных вида

| QR | Где | Назначение |
|---|---|---|
| Wi-Fi (`WIFI:S:...;T:WPA;P:...;;`) | вход в офис | Инфраструктура, не игра: камера телефона подключается к сети сама. Только для гостевой сети — корпоративная обычно 802.1X, её пароль в QR светить нельзя |
| Статичный QR комнаты | у двери каждой комнаты | Запасная навигация: скан → персонаж переносится в комнату. Для Web, выключенного Bluetooth, севшего маяка |
| Ротируемый QR на экране | ключевые точки (ресепшн, кухня и т. п.) | Доказательство присутствия для наград: TOTP-подобный токен, срок жизни 30–60 с, секрет только на сервере |

Основной сценарий с BLE: пришёл в комнату → персонаж перешёл сам. QR комнаты — ручной вариант.

### Приватность

- Историю перемещений не хранить. На сервер отправлять только события «задание в зоне X».
- Отслеживание сотрудников работодателем — персональные данные (152-ФЗ): явное согласие и экран «что мы собираем и зачем».

### Итоговая модель присутствия

1. **IP офиса** — доступны ли задания вообще.
2. **Зона (BLE, запасной вариант — QR комнаты)** — в какой комнате игрок.
3. **Ротируемый токен (QR на экране)** — подтверждение для начисления наград.

## 3. Мини-игры

### Техническая база

- **Микрофон** — ядро Godot: `AudioStreamMicrophone` + `AudioEffectCapture` (сырые сэмплы) / `AudioEffectSpectrumAnalyzer` (FFT). Включить `audio/driver/enable_input`, на Android — разрешение `RECORD_AUDIO`. Работает и в Web.
- **Акселерометр / гироскоп** — `Input.get_accelerometer()`, `Input.get_gyroscope()`. В Web — DeviceMotion; в iOS Safari нужен явный запрос разрешения.
- **Шагомер** — нативно через `PlatformServices`: Android `TYPE_STEP_COUNTER`, iOS `CMPedometer`.
- **Камера + ML** — расширение нативного плагина, который уже нужен для QR:
  - Android — ML Kit (pose detection, face detection, image labeling);
  - iOS — Vision (`VNDetectHumanBodyPoseRequest`, face landmarks);
  - Web — MediaPipe Tasks JS.
  Плагин отдаёт в GDScript готовые результаты (ключевые точки, число лиц, метки), а не кадры.
- **Превью камеры** — плагин отдаёт кадр низкого разрешения (~160×120, ~15 fps) → `ImageTexture` + шейдер пикселизации/CRT, чтобы картинка вписывалась в стиль игры.
- **Приватность** — кадры камеры и звук не покидают устройство.

### Утверждённые игры

| # | Игра | Сенсоры | Реализация |
|---|---|---|---|
| 1 | «Донеси кофе» — с кухни в переговорку, не расплескав | акселерометр + зоны | Старт в зоне «кухня», финиш в зоне «переговорка», наклон телефона не выше порога, ограничение по времени |
| 2 | «Лестница, не лифт» — шаги по офису | шагомер | **Только подсчёт шагов** (этажи и барометр не используем) |
| 3 | «Найди предмет» (кружка, растение, монитор) | камера | ML Kit image labeling, метки базовой модели, порог 0.55 |
| 4 | «Утренняя зарядка» — 10 приседаний | камера | Pose detection, угол в колене → счётчик повторов |
| 5 | «Спой ноту» / «камертон» | микрофон | Определение высоты тона (автокорреляция / YIN) по буферу `AudioEffectCapture` |
| 6 | «Скороговорка» | микрофон | Android `SpeechRecognizer` / iOS `SFSpeechRecognizer` (русский). На части Android распознавание идёт через облако Google → зависит от сети. Офлайн-вариант: Vosk (Apache 2.0, русская модель ~45 МБ). Самая сложная из списка |
| 7 | «Фото с коллегой» | камера | Сервер назначает коллегу, который сегодня отметился в офисе; ≥2 лица в кадре (ML Kit / Vision, улыбка только даёт бонус); коллега подтверждает фото во входящих своей игры, награда ждёт подтверждения |
| 8 | «Охота за предметами» (кулер, растение, логотип) | камера | Первый этап — свои метки ArUco (надёжно, бесплатно, OpenCV). Распознавание реальных объектов (TFLite / Core ML) — позже, если хватит времени |
| 9 | Задания на знакомство (этаж аналитики): «Кофе вслепую», «Бинго знакомств», «Объясни свою работу» | камера (QR) | Скан «Мой QR» коллеги; сервер проверяет назначенного коллегу, другой департамент, отметку коллеги в офисе, повтор за день |

### Отклонённые игры

- «Остуди кофе» (дуть в микрофон).
- «Ультразвуковое рукопожатие» (обмен токеном между телефонами через звук).

### Антифрод для мини-игр

Результат мини-игры считается на клиенте, поэтому доверять ему нельзя (правило 1):

- награда выдаётся только при валидном доказательстве присутствия (IP офиса + ротируемый токен) и в пределах дневного лимита на сервере;
- задание засчитывается только из набора игрока на сегодня, в часы заданий и не раньше паузы после предыдущего; непрерывная игра ограничена с обязательным отдыхом (настраивает администратор, см. README «Рабочее время прежде всего»);
- очки мини-игры влияют только на множитель награды, с потолком;
- для дорогих заданий — фото на ручную модерацию.

### Предлагаемый порядок

1. «Донеси кофе», «Лестница» — без ML, минимум нативного кода.
2. «Найди красное», «Утренняя зарядка», «Фото с коллегой», «Охота за предметами» (ArUco) — ML-часть плагина камеры.
3. «Спой ноту», «Скороговорка» — обработка звука и распознавание речи.

## Вопросы

### IT офиса

1. Есть ли в офисе BLE-маяки? Многие корпоративные точки доступа Wi-Fi (Cisco, Aruba, Juniper Mist) имеют встроенный BLE. Если есть: модель, формат (iBeacon / Eddystone), UUID, схема расстановки по комнатам.
2. Какой у офиса внешний IP (диапазоны IPv4 и IPv6)? Есть ли отдельная гостевая сеть? Какой IP у VPN-шлюза (исключить из белого списка)?

### Заказчик

1. Предусмотрены ли взаимодействия пользователей внутри игры друг с другом: обмен наградами, отправка реакций и сообщений, статусы?
2. Предусматривает ли игра штрафные меры для пользователей при игнорировании событий и невыполнении их? Пример: не пришёл в офис, не выполнил какое-либо действие.
3. Предусмотрена ли кастомизация персонажа? Сможет ли пользователь настроить свой виртуальный образ в игре: причёска, одежда, аксессуары и остальное?
4. В каком виде пользователь должен получать уведомления от игры? Если ограничиться только вебом — почта и уведомления внутри игры; если приложение — push-уведомления от приложения.
5. Нужна ли админ-панель, через которую привилегированный пользователь получит следующую статистику и функции:
   - история начисления баллов;
   - история выполнения игровых событий пользователями;
   - список всех пользователей и информация об их профилях;
   - возможность списывать и начислять баллы пользователям.
6. Какие награды сможет получить пользователь за очки? Сколько очков соответствует какой награде? Список наград можно прислать списком; если есть представление о ценообразовании — его тоже.
