# Тестирование на iPhone через веб-версию

Заметки по итогам обсуждения (2026-09-17).

**Цель.** Полноценно тестировать сервис (камера, QR, датчики, сервер) на реальных iPhone без Xcode и Apple ID,
пока нет нативного iOS-плагина. Заодно это закрывает v2 (Web) из CLAUDE.md.

**Статус на 2026-10-03.** Мост умеет всё, что нужно мини-играм. К прежнему добавлены поза для
приседаний (MediaPipe Pose Landmarker lite), предметы (детектор EfficientDet-Lite0 с классами COCO и
классификатор EfficientNet-Lite0 с классами ImageNet, метки обеих моделей объединяются), метки ArUco
DICT_4X4_50 (js-aruco2) и речь (Web Speech API, `webkitSpeechRecognition` в Safari). Список предметов
«Найди предмет» подобран под классы этих моделей: маркерной доски в них нет, её заменили клавиатура и
бутылка. Микрофон для речи запрашивается до начала задания.

**Статус на 2026-09-23 (устарел).** Мост сделан (`client/platform/web/camera_bridge.js`): камера с превью,
QR через jsQR, лица и улыбки через MediaPipe Face Landmarker, разрешение на датчики движения для iOS
(запрашивается при первом касании страницы) и шагомер по акселерометру. Библиотеки грузятся с
`cdn.jsdelivr.net` и `storage.googleapis.com`, телефону нужен интернет. Поза, ArUco, распознавание
предметов и речь пока не подключены: эти задания уходят в запасные варианты или недоступны.

**Статус на 2026-09-17 (устарел).** В `client/platform/web/web_platform.gd` работают только акселерометр (через ядро
Godot) и микрофон. Камера, QR, MediaPipe и распознавание речи возвращают «не поддерживается», задания
уходят в запасные варианты. Запрос разрешения на датчики для iOS (`DeviceMotionEvent.requestPermission()`)
не реализован, поэтому на iPhone акселерометр, скорее всего, молчит.

## 1. Почему веб, а не нативная сборка

- Нативная iOS-сборка требует Xcode на Mac (полный Xcode, не Command Line Tools) и подписи Apple ID.
  С бесплатным аккаунтом сборка живёт 7 дней, TestFlight доступен только в платном ($99/год).
- iOS-плагина (AVFoundation, Vision, CoreMotion) пока нет, поэтому нативная сборка сейчас так же урезана, как веб.
- Safari на iOS даёт почти всё нужное через веб-API. Технических ограничений на камеру и QR нет, не хватает
  только моста между JS и Godot.

Ограничение подхода: так проверяются сервер, игровая логика, задания и UX на реальном iPhone, но не будущий
нативный iOS-плагин (v1) — это отдельный код.

## 2. Что даёт Safari на iOS

Всё ниже работает только в защищённом контексте (HTTPS).

| Функция | Веб-API | Замечания |
|---|---|---|
| Камера | `getUserMedia` | у `<video>` нужны `playsinline` и `muted` |
| QR | jsQR (чистый JS) | `BarcodeDetector` в Safari нет, на него не рассчитываем |
| Поза, лица, предметы | MediaPipe Tasks JS (WASM + WebGL) | работает на iPhone, нужен замер fps |
| Акселерометр / гироскоп | `DeviceMotionEvent` | на iOS обязателен `requestPermission()` по нажатию пользователя |
| Шагомер | нет API | считаем шаги сами по акселерометру, точность ниже нативной |
| Речь | `webkitSpeechRecognition` | нестабилен, зависит от версии iOS, нужен интернет |
| Геолокация | Geolocation API | слабый фактор, только в паре с QR |
| Микрофон | ядро Godot (`AudioStreamMicrophone`) | уже работает |

## 3. План реализации моста

Правило из CLAUDE.md сохраняется: игровой код работает только с `PlatformServices`, `JavaScriptBridge`
используется только внутри `client/platform/web/`.

1. **JS-модуль.** Подключается в `index.html` через `html/head_include` пресета Web вместе с jsQR и MediaPipe
   (с `cdn.jsdelivr.net` или локальной копией). Модуль открывает камеру, обрабатывает кадры в JS и отдаёт
   в Godot только готовые результаты: текст QR, ключевые точки, число лиц, метки. Сырые кадры не уходят
   из браузера (приватность, как на Android).
2. **`web_platform.gd`.** Вызывает функции модуля через `JavaScriptBridge`, принимает колбэки
   (`JavaScriptBridge.create_callback`) и испускает те же сигналы `PlatformServices`, что и Android-реализация.
   `has_feature()` возвращает `true` для реализованных функций.
3. **Превью камеры.** JS рисует кадр ~160×120 в offscreen canvas, отдаёт байты в Godot → `ImageTexture` +
   шейдер пикселизации/CRT. Та же схема, что на Android.
4. **Разрешения.** Кнопка «Начать» в игре: по нажатию запрашиваем камеру и `DeviceMotionEvent.requestPermission()`.
   Без жеста пользователя iOS отказывает.
5. **Шагомер.** Детектор шагов по модулю ускорения (фильтр + порог + минимальный интервал между шагами).

Порядок работ: камера + QR → датчики (разрешение iOS, шагомер) → MediaPipe → речь.

## 4. Запуск на телефоне в одной Wi-Fi сети с Mac

Всё поднимает один скрипт (macOS, нужны Docker, Godot 4.7.2 с шаблонами Web-экспорта и Node.js):

```bash
./run-lan.sh
```

Скрипт:
1. Берёт адрес Mac в Wi-Fi (`en0`) или адрес из аргумента.
2. Создаёт локальный центр сертификации и сертификат для этого адреса (`tools/lan/make-certs.sh`,
   файлы в `server/certs`, в git не попадают). Связку ключей Mac он не трогает.
3. Собирает веб-версию игры в `build/web` и админку в `admin/dist` (`--skip-build` пропускает сборку).
4. Запускает Nakama, PostgreSQL и Caddy (`docker compose --profile lan`).

Адреса:

| Адрес | Что |
|---|---|
| `http://<ip>:8080` | Страница с сертификатом и инструкцией для телефона |
| `https://<ip>:8443` | Игра |
| `https://<ip>:5443` | Админка |
| `https://<ip>:6443/#key=<NAKAMA_HTTP_KEY>` | Экран офиса для ноутбука: коды входа и выхода, коды всех комнат. Полную ссылку печатает `run-lan.sh`; только для ноутбука, не для телефонов |
| `https://<ip>:7443` | API Nakama через Caddy (игра и админка сами ходят сюда со страниц HTTPS) |

На каждом iPhone один раз:
1. Открыть в Safari `http://<ip>:8080`, скачать сертификат, разрешить загрузку профиля.
2. Настройки → Основные → VPN и управление устройством → «Office Game LAN CA» → Установить.
3. Настройки → Основные → Об этом устройстве → Доверие сертификатам → включить «Office Game LAN CA».
4. Открыть `https://<ip>:8443`. Разрешить камеру; при первом касании экрана Safari спросит доступ
   к движению и ориентации, нужно разрешить.

Сертификат сервера действует 397 дней и пересоздаётся, если сменился адрес Mac. Центр сертификации
живёт 10 лет; если удалить `server/certs`, его придётся заново ставить на телефоны.

Если телефон не открывает страницы, разрешите входящие подключения для Docker в брандмауэре macOS.

**Альтернатива без сертификатов:** туннель `cloudflared tunnel --url http://localhost:8060` даёт настоящий
HTTPS-адрес, но только для одного порта: для Nakama нужен второй туннель и сборка с его адресом.

## 5. Сервер

- Для настоящего теста поставьте в `server/.env` `DEV_MODE=false`: dev-RPC выдают код входа любому
  игроку и позволяют менять часы и начислять коины. `run-lan.sh` предупреждает об этом.
- Аккаунты участникам выдаёт администратор в админке (`https://<ip>:5443` с телефона или
  `http://localhost:5173` с Mac после `npm run dev`).
- Экран у ресепшна: страница `https://<ip>:6443/#key=...` в браузере ноутбука (`tools/office-screen`) или окно
  Godot на Mac (`./run.sh --office-screen`).
- QR-коды комнат печатаются скриптом `tools/printables/make_printables.py`.
- Сеть офиса (`OFFICE_NETWORKS` в `server/.env`) для `run-lan.sh` оставьте пустой. Docker Desktop на
  macOS не передаёт контейнерам адреса телефонов: все запросы приходят с адреса шлюза Docker (172.x).
  Роль второго фактора здесь играет сама сеть: сервер доступен только из Wi-Fi, к которому подключён Mac.

### Домашний Wi-Fi как сеть офиса

`./run-lan.sh --office-net` включает проверку сети офиса на любом Wi-Fi. Caddy запускается на самом Mac
(`brew install caddy`, конфиг `server/caddy/Caddyfile.host`), видит настоящие адреса телефонов и пишет их
в `X-Forwarded-For`. Порты Nakama 7350 и 7351 в этом режиме открыты только на `127.0.0.1`, иначе телефон
подделал бы заголовок в обход Caddy.

Настройки роутера менять не нужно.

1. Сеть офиса: подсеть Wi-Fi, например `10.20.30.0/24`. `OFFICE_NETWORKS` в `server/.env` читается только
   при первом запуске; на существующей базе задайте сеть в админке («Офисы»).
2. Проверка отказа: временно поставьте в админке чужую сеть (`10.0.0.0/24`). Все телефоны получат
   `office_network_required`, попытка появится в журнале подозрительных действий. Потом верните подсеть Wi-Fi.
3. Если роутер выдал Mac другой адрес, запустите `./run-lan.sh --office-net` заново без `--skip-build`:
   сертификат и сборка обновятся, сертификат CA на телефонах ставить заново не нужно.
4. Если телефон не открывает `http://<ip>:8080`, проверьте брандмауэр macOS (входящие для `caddy`). Если не
   помогло, в роутере может быть включена изоляция клиентов (AP isolation): тогда используйте другую сеть.
5. Остановить: `caddy stop` и `docker compose down` в `server/`.

### Сеть офиса на настоящем сервере

Вход по коду, задания, коды комнат и выбор коллеги засчитываются только с адресов из `OFFICE_NETWORKS`:
CIDR-префиксы или отдельные адреса через запятую, IPv4 и IPv6. Иначе сервер отвечает
`office_network_required` и пишет попытку в журнал подозрительных действий вместе с адресом.

- Укажите внешние (NAT) адреса офиса и его IPv6-префикс. Адрес шлюза корпоративного VPN не указывайте:
  иначе VPN из дома будет выглядеть как офис.
- Nakama берёт адрес клиента из первого значения `X-Forwarded-For` и доверяет этому заголовку. Порт 7350
  должен быть закрыт снаружи. Клиенты ходят только через прокси, который перезаписывает заголовок
  (Caddy делает так по умолчанию).
- Cloudflare и другие CDN дописывают свой адрес в конец `X-Forwarded-For`, а начало заголовка оставляет
  клиенту. За таким CDN настройте в прокси доверенные адреса CDN (`trusted_proxies`, `client_ip_headers`
  в Caddy), чтобы до Nakama доходил настоящий адрес клиента.

## Чек-лист встречи

Подробный чек-лист теста: [lan-test-checklist.md](lan-test-checklist.md).

1. `DEV_MODE=false`, `./run-lan.sh`, экран ресепшна на Mac, распечатанные коды комнат.
2. В админке выдать двум участникам аккаунты в разных департаментах.
3. На обоих iPhone поставить сертификат, открыть игру, войти.
4. Отсканировать ВХОД на экране Mac, потом код комнаты.
5. Фото с коллегой: один начинает задание, второй подтверждает во входящих.
6. «Слепой кофе»: сканировать «Мой QR» второго игрока.
7. Отсканировать ВЫХОД: задания и коды комнат больше не засчитываются.

## 6. Ограничения веб-версии

- Производительность Godot-web в Safari ниже нативной. Ориентир: 360×640, ML на 15 fps. Нужно замерить
  на старых iPhone.
- Если закрыть вкладку или свернуть Safari, камера и датчики отключаются.
- BLE и push-уведомления в вебе недоступны (см. CLAUDE.md).
- Для полного теста всего сервиса уже сейчас есть Android: нативный плагин готов.
